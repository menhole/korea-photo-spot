# PHOTO SPOT KOREA · 개인용 웹사이트 v3

기존 사이트를 바탕으로 개인 사진 지도 + 여행 일기 + 사진 명소 탐색 탭으로 바꾼 버전입니다. 앱 설치 없이 GitHub Pages에서 일반 웹사이트로 사용할 수 있습니다.

## 이번 버전의 기능

- **가고 싶은 곳:** 개인 장소 저장, 태그/메모, 지도 표시, 방문 완료 처리
- **다녀온 곳:** 날짜별 여행 일기, 태그, 사진 업로드, 지도 표시
- **사진 명소:** 서울·수도권 중심의 시작 명소 목록, 지역/이름 검색, 태그 필터, 세로형 리스트 표시 (명소 탐색 탭에는 지도 없음)
- **계정 동기화:** 같은 Supabase 계정으로 로그인하면 PC와 태블릿에서 같은 개인 기록을 확인
- **개인정보:** 개인 장소와 일기는 로그인한 본인만 읽고 수정할 수 있도록 RLS 적용
- **일기 사진:** `private-diary` 비공개 Storage bucket에 저장하고 로그인 사용자에게만 임시 URL 제공

## 중요: 기존 설정 파일 보존

이 ZIP에는 `config.js`를 넣지 않았습니다. 기존 GitHub 저장소의 실제 `config.js` 파일을 그대로 유지하세요. 이 파일을 실수로 덮어쓰지 않도록 주의하세요. 새로 만들어야 한다면 `config.example.js`를 복사해 `config.js`로 이름을 바꾼 뒤 기존 Supabase `SUPABASE_URL`과 `SUPABASE_PUBLISHABLE_KEY` 값을 입력하세요.

브라우저에 넣으면 안 되는 키: `service_role`, `sb_secret_...` 등 비밀 키. `sb_publishable_...` 또는 프로젝트의 `anon` 공개 키만 사용합니다.

## Supabase 마이그레이션

1. Supabase Dashboard → SQL Editor를 엽니다.
2. `supabase-migration.sql` 전체를 붙여넣고 Run을 누릅니다.
3. 실행 후 Table Editor에서 `my_places`, `diary_entries`, `photo_spots`가 생성됐는지 확인합니다.
4. Storage → Files에서 `private-diary` 버킷이 생성됐는지 확인합니다.

**기존 데이터 보존:** 이 SQL은 기존 `spots` 테이블이나 `spot-photos` 버킷을 삭제하지 않습니다. 기존 `spots`의 본인 소유 데이터는 `photo_spots`에 중복 없이 복사됩니다. 기존 31개 장소를 포함해 이름이 중복되지 않는 데이터가 들어갑니다. 기존 `spots`는 본인 계정만 읽도록 RLS를 바꿉니다.

기존 `spot-photos` 버킷은 이번 마이그레이션에서 비공개로 전환됩니다. 따라서 예전에 저장된 공개 사진 URL은 더 이상 바로 열리지 않을 수 있습니다. 기존 사진 파일 자체는 삭제하지 않으며, 본인 계정 폴더의 사진만 읽을 수 있도록 제한합니다. 새 일기 사진도 별도의 비공개 저장소에 저장됩니다.

## GitHub에 반영하기

1. 먼저 GitHub 저장소에서 현재 파일을 백업하거나 ZIP으로 내려받으세요.
2. 이 ZIP의 `index.html`, `app.js`, `styles.css`, `icon.svg`, `supabase-migration.sql`, `README.md`를 저장소 루트에 올려 기존 파일을 교체합니다.
3. `config.js`는 기존 프로젝트 URL/Publishable key가 들어 있는 파일을 유지하거나, 위에서 설명한 대로 값을 복사하세요.
4. Supabase에서 Authentication → Settings의 신규 회원가입 허용 설정을 끄면, 기존 계정 로그인만 가능한 개인용 사이트로 운영할 수 있습니다.
5. GitHub 저장소의 Settings → Pages에서 `main` 브랜치, `/(root)`가 선택되어 있는지 확인합니다.
6. 몇 분 후 GitHub Pages 주소를 새로고침합니다.

## 테스트 순서

1. 로그인합니다.
2. 가고 싶은 곳 → 장소 저장 → 지도에서 위치 선택 → 저장.
3. 다른 기기에서 같은 계정으로 로그인해 장소가 보이는지 확인.
4. 다녀온 곳 → 일기 쓰기 → 방문 날짜/사진/태그/기록 입력 → 지도에서 위치 선택 → 저장.
5. 사진 명소에서 지역과 태그로 검색하고, 가고 싶은 곳에 저장합니다.

## 사진 명소 데이터의 한계

처음 제공되는 명소는 서울·수도권 중심의 기본 목록입니다. 인스타그램·블로그의 모든 게시물을 실시간으로 자동 수집하는 기능은 아닙니다. 각 플랫폼의 접근 제한과 게시물 권리 문제 때문에 모든 게시물을 자동 복제할 수는 없습니다. 공개적으로 확인할 수 있는 장소를 관리자가 목록에 추가하는 방식으로 확장할 수 있습니다. 장소 좌표는 지도 표시용 근사값이므로 방문 전 운영 시간, 출입 가능 여부, 촬영 제한을 확인하세요.

## 실시간 검색 + 외부 검색 함께 사용하기

사진 명소 탭은 두 가지 검색 경로를 지원합니다.

- **사이트 안 실시간 검색:** Tavily 검색 API를 Supabase Edge Function을 통해 호출합니다. API 키는 서버 비밀 변수에만 보관하며 `config.js`나 브라우저 코드에 넣지 않습니다.
- **외부 검색:** 네이버 검색과 Google 검색 버튼은 API 연결 여부와 상관없이 사용할 수 있습니다. 검색 결과는 해당 검색 사이트에서 열립니다.

### 사이트 안 실시간 검색 연결 (Tavily)

Tavily 무료 Researcher 요금제는 현재 월 1,000 API 크레딧을 제공하고 카드 등록이 필요 없다고 안내합니다. 정책은 바뀔 수 있으니 신청 화면에서 최신 조건을 확인하세요.

1. Tavily 계정에서 API 키를 발급합니다: https://app.tavily.com/
2. Supabase Dashboard → Edge Functions에서 `photo-spot-search` 함수를 배포합니다. 이 ZIP의 `supabase/functions/photo-spot-search/index.ts` 파일 내용을 함수 코드로 사용합니다.
3. Supabase Dashboard → Edge Functions → Secrets에 `TAVILY_API_KEY` 이름으로 Tavily 키를 등록합니다.
4. 함수의 JWT 검증은 켜 둡니다. 사이트에 로그인한 상태에서 실시간 검색 버튼을 누르면 함수가 호출됩니다. 검색 API 계정 가입 시 연령 및 이용 약관 조건은 보호자와 확인하세요.
5. `config.js`의 Supabase URL과 Publishable key가 올바른지 확인합니다. 기존 `config.js`는 이 ZIP에 포함하지 않았으며, 저장소의 기존 파일을 그대로 유지하세요.

**주의:** Tavily 키를 `config.js`, `app.js`, GitHub 저장소 또는 채팅에 붙여넣지 마세요. API 키는 Supabase Edge Function Secrets에만 보관합니다. API 무료 한도를 다 쓰면 사이트 내 검색은 멈출 수 있지만 네이버·Google 외부 검색 버튼은 계속 작동합니다.

### 모바일에서 사용할 때

- 사이트에 로그인한 뒤 사진 명소 탭에서 지역·테마를 선택하고 `실시간 검색`을 누릅니다.
- API 연결 전이나 오류가 있을 때는 `네이버 검색` 또는 `구글 검색`을 누릅니다.
- 검색 결과의 `원문 보기`를 눌러 실제 게시 내용을 확인합니다.
- 검색 결과를 저장하면 `가고 싶은 곳`에 추가됩니다. 검색 결과는 위치 좌표를 보장하지 않으므로 저장 후 지도 핀은 자동으로 생기지 않을 수 있습니다.


## 여행 버킷리스트 개편판 (2026-11)

이번 버전은 기존 장소/방문 기록 기능을 지도 메뉴 아래에 모으고, 홈 노트·여행 버킷리스트·캘린더를 추가했습니다. 사진 명소 실시간 검색 UI는 보류했으며, 나중에 API를 연결할 수 있도록 별도 기능으로 다시 추가할 수 있습니다.

### 새 기능을 위한 Supabase 설정
1. Supabase 대시보드의 SQL Editor를 엽니다.
2. ZIP 안의 `travel-planner-migration.sql` 전체 내용을 실행합니다.
3. 기존 `config.js`는 그대로 유지하고, 이 ZIP의 파일로 덮어쓰지 마세요. `config.js`는 보안을 위해 ZIP에 포함하지 않았습니다.
4. 기존 파일을 새 파일로 교체한 뒤 사이트를 새로고침하고 로그인합니다.

추가되는 테이블은 `travel_notes`, `travel_buckets`, `travel_events` 세 개이며, 각 테이블은 로그인한 사용자 본인 데이터만 읽고 수정할 수 있도록 RLS 정책이 적용됩니다. 기존 `my_places`와 `diary_entries` 테이블 및 데이터는 수정하거나 삭제하지 않습니다.

### 메뉴 구성
- 메인 화면: 빠른 메모와 최근 노트 (별도 탭 없이 첫 화면에 표시)
- 지도: 기존 가고 싶은 곳 지도와 다녀온 곳/사진 일기 지도
- 버킷리스트: 목표 추가, 완료 체크, 삭제
- 캘린더: 월별 달력, 날짜별 일정 추가 및 삭제

참고: 새 기능을 사용하려면 `travel-planner-migration.sql`을 먼저 실행해야 합니다.


## 아이디 + 비밀번호 로그인 설정 (이메일 불필요)

이 버전은 화면에서 이메일을 받지 않고 아이디와 비밀번호로 가입·로그인합니다. Supabase Auth 내부에서는 아이디를 `psk_<아이디>@photospot.invalid` 형식의 예약된 가상 이메일 식별자로 변환합니다. 이 주소는 실제 이메일 주소가 아니며 메일을 받을 수 없습니다.

1. Supabase Dashboard → Authentication → Sign In / Providers → Email로 이동합니다.
2. **Confirm email을 OFF**로 설정하고 저장합니다. 이메일 인증을 끄지 않으면 가상 주소로 인증 메일을 받을 수 없어 가입이 완료되지 않습니다.
3. Custom SMTP를 이 로그인 방식에 사용할 필요는 없습니다. 설정해 둔 Gmail SMTP는 더 이상 필요하지 않으므로 원하면 Custom SMTP를 끌 수 있습니다.
4. GitHub 저장소에는 이 ZIP의 `index.html`, `app.js`, `styles.css` 등을 업로드하되, 기존 `config.js`는 절대 덮어쓰거나 삭제하지 마세요.

아이디 규칙: 영문 대소문자·숫자·밑줄(`_`)·하이픈(`-`)만 사용, 4~20자. 아이디는 대소문자를 구분하지 않습니다. 비밀번호는 8자 이상입니다. 이메일을 사용하지 않으므로 비밀번호 재설정/계정 복구가 제공되지 않습니다. 아이디와 비밀번호를 안전하게 보관하세요.

**기존 이메일 계정 안내:** 기존 이메일 계정은 자동으로 아이디 계정으로 변환되지 않습니다. 기존 계정의 데이터는 삭제되지 않지만, 새 아이디 계정은 별도의 사용자로 취급되어 기존 기록이 자동으로 연결되지 않습니다. 기존 계정에 중요한 기록이 있다면 전환 전에 별도 이전 작업이 필요합니다.
